# Internationalisation (i18n)

## Purpose

Describes how translations are registered in `src/i18n`.

## Core resources

- `src/i18n/index.ts` initialises one shared i18next instance (exported as `i18n`) with the Spanish locale (`lng` and `fallbackLng` are `es`) and `escapeValue: false`.
- The core namespaces are `common` (the default namespace), `shell`, `home`, `processes`, `processDetail`, `execution`, `admin` and `errors`, loaded from `src/i18n/locales/es/<namespace>.json`. Their types come from the bundled resources, so `t` keys are checked at compile time.
- Code outside React (for example `shared/lib/status.ts` and `shared/lib/errors.ts`) calls `i18n.t` with a namespaced key such as `common:processStatus.ok`.

## Registering extra namespaces

- `registerTranslations(namespace, lng, resources)` registers an extra namespace bundle in the shared i18next instance, using `addResourceBundle(lng, namespace, resources, true, true)` (deep merge and overwrite).
- It is used by optional modules such as `src/oos`.
- Contribution keys (`labelKey`, `header`) may be namespaced, for example `oos:nav.calendar`; they are resolved with `useTranslateKey` (see [extension framework](architecture/extension-framework.md)).
